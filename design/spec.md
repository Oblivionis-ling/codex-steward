# 个人管家界面规格

本文记录 0.1.0 的界面与验证。下一版以 [新版任务看板设计说明](个人管家_设计说明_Ling_20261002_需求确认稿.md) 为需求依据，当前尚未实施新版。

视觉依据为 `concept.png`（Image Gen，1536 × 1024）。完整提示要求纸质浅色、原生可交互控件、左侧导航、三态输入、分隔线列表、待办聊天按钮；无插画、渐变和仪表盘。

- 纸色 `#f8f5ef`、面色 `#fffdf8`、墨色 `#252823`、弱文字 `#767872`、边线 `#dddcd4`、绿 `#36584b`。
- 桌面侧栏 258px，主区边距 40px；宋体主标题，微软雅黑控件；标题 52px，正文 18px，控件 16px。小屏下缩至 14–16px。
- 图标为 1.65px 轮廓线：笔记本、文档、勾选框、对话、柱状回顾、目录、数据库、设置、月亮、箭头。
- 共用组件为按钮、输入、分隔线记录行、筛选胶囊、抽屉；不使用卡片网格。
- 允许首屏文案：个人管家、全部记录、待办、智能问答、阶段回顾、分类、工作、学习、灵感、生活、本地保存、设置、搜索记录…、全部归档、把零散的念头，留给未来的自己。、想法、资料、记下一闪而过的想法…、保存记录、全部、未归档、已归档、归档、开始聊天。
- `?demo=1` 仅作设计展示，显示概念中的四条示例，不写入用户数据。实际安装初始化为空库，显示录入提示。
- 必要延伸：记录抽屉支持编辑和标签筛选；待办有完成/优先级；问答列出可点击来源；回顾有日期和建议行动；设置支持当前 Codex/自选模型、导入导出与本地 Key。
- 从待办开始聊天使用官方 `codex://new`，明确携带 `F:\workspace` 和原始待办，打开已填内容的聊天输入框，用户发送后开始执行。
- 动效仅用于抽屉和保存反馈；尊重 reduced-motion。深色切换复用变量，移动端导航横向排列。

原生侧栏注册使用官方 MCP Extensions 的 global entrypoint，同时提供 thread entrypoint。官方说明：https://developers.openai.com/plugins/build/extensions 。聊天深链接：https://learn.chatgpt.com/docs/reference/commands 。

## 最终设计提示规格

以下为概念生成要求的归一化记录，使用内置 Image Gen，输出保存为 `concept.png`：

> 生成完整中文个人信息管家桌面应用界面，1536 × 1024。浅色奶油纸质背景、墨色文字、克制绿色强调、宋体主标题、清晰中文控件。左侧为个人管家、全部记录、待办、智能问答、阶段回顾，下面有分类和本地保存、设置、主题按钮。主区顶部为全部记录、说明句、搜索记录、全部归档；其下是想法/资料/待办三态输入和保存记录，再下是全部/未归档/已归档筛选与四条分隔线记录。记录行有类型、标题、描述、分类、标签或优先级，待办右侧有开始聊天。所有文本与控件应能用原生 HTML/CSS 实现。无插画、渐变、仪表盘或无关指标；避免卡片网格。

## 最终浏览器比较

已通过 `view_image` 对照概念与最终浏览器截屏 `preview.png`：

1. 结构：258px 侧栏、主区标题/搜索/输入/筛选/四行列表的顺序及留白保持一致。
2. 文案：导航、三态、主标题、说明句、行标题与聊天按钮对应概念；演示样例与实际空库明确区分。
3. 字体：宋体标题和记录主文、中文控件层级一致；浏览器中文字体栅格化与生成参考略有差别。
4. 色彩：纸色背景、绿色强调、浅边线、柔和类型标签保持一致；深色复用同一变量体系。
5. 容器与图标：输入框及分隔线列表、轮廓按钮、细线图标对应规格；图标使用可维护的 Lucide 系统。
6. 状态与响应：空输入的保存按钮禁用是实际交互状态；小屏收拢导航且无文档横向溢出，日期输入和操作仍可访问。

## 减法审查

实际目标是「记录 → 整理 → 待办 → Codex 聊天」。保留本机 JSON、单个 MCP 服务和同一份界面即可满足。无需额外数据库、登录体系、后台定时器或公网托管；模拟模型已停止，QA 数据与中间过程文件已移出项目，保留运行依赖和构建产物。现有流程已足够简洁，本轮不增加基础设施。
