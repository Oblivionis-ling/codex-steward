# 0.3.1 阶段判断与清空验证

验证日期：2026-10-03。

## 问题与修正

试用中的四张卡片继承了旧 JSON 的阶段：旧版 `ready` 直接迁为新版 `shaping`。这次迁移没有重新执行 AI 分析，不能把原迁移阶段当作完整聊天的最新结论。用户明确更正，这四个项目都已在实际推进。

原分析说明也会把最近出现的盘问、调研当作构思，遗漏项目已有制作和持续迭代。因此本版改为判断整个项目的生命周期：

- 灵感池：零散想法，尚未展开明确目标。
- 构思中：尚未制作目标产物，正在讨论需求或开发前方案；或用户明确将整个项目退回重新构思。
- 进行中：已经开始推进目标产物，仍在制作、修订、迭代、处理阻塞或等待整体目标确认。调研报告、小说大纲、设计规范本身也可以是目标产物。
- 待验收：整个当前目标完整交付，并明确交给用户最终验收。小版本发布、部分功能、候选大纲和一次技能回答不足以送验。
- 已结项：用户明确验收并结束整个当前目标。确认方向、登录成功和阶段性确认不等于结项；后续新修改请求恢复进行中。

聊天闲置或当前回合结束表示执行状态，不抹掉项目已有进展。模型建议附带阶段里程碑；服务核对回合 ID、角色、原文和时间顺序，拒绝伪造引用与助手代替用户的验收。自动建议按这些里程碑校正，保存时保留用户手动选择的阶段，运行状态与原文保护仍生效。

历史来源增加逐轮时间线，保留头尾截取可能遗漏的中段制作。长回合的文本仍受预算限制，不能声称模型看到了任意长度聊天的每个字；阶段建议保留置信度和可查看的原文。

清空前核对正式服务的版本、数据目录、进程命令行和整理状态；仅停止本插件 HTTP 进程。脚本先用 SQLite 备份 API 保存快照，再在事务内清空卡片、归档卡、评论、活动、附件、关系和整理建议，重置本地编号。

实际清空 4 张卡片；归档卡与整理建议原本均为 0。清空后正式服务、只读 SQLite 核对与重开检查均显示空库，外键检查无错误。快照保留原 4 张卡片及活动，旧 JSON 哈希未变；原生 Codex 聊天保留，新库文件继续存在，重开不会重新迁入旧卡。

已安装 `personal-steward@ling-local` 0.3.1。缓存中的 MCP、HTTP、单文件 UI、插件清单、技能与写回 CLI 六个文件哈希均与项目构建或源文件一致。正式服务 health 和 state 返回 0.3.1，实际服务提供的 UI 字节哈希与最后构建一致。

手动后台启动命令曾被自动审批以 `blocked by policy` 拒绝；随后发现正常插件 broker 已自动重启同一目录的新版服务。已核对该进程身份、版本与空库，没有重复启动服务，也没有停止 Codex 桌面应用。
