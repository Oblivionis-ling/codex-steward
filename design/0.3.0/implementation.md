# 0.3.0 实施说明

日期：2026-10-03。目标是让用户把零散灵感逐渐想清楚，明确选择实施，再查看交付与验收。首版可测试，后续用小版本调整使用体验。

## 流程取舍

五栏改为灵感池、构思中、进行中、待验收、已结项。构思包含普通讨论、grill-me 盘问与 idea-research 调研，没有固定顺序、必做次数或结束后自动实施。选择技能本身来自用户在卡片内的操作。

默认一项想法一张卡，一个主聊天。需要独立跟进时再拆一层子任务，父卡显示汇总。父卡回退停止全部关联主聊天并重置子任务到构思中；停止失败保留原阶段。交付只允许实施回合保存，最终验收由用户完成。

本版保留宿主原生聊天。新聊天预填说明，用户发送；已有聊天复制说明后打开，用户粘贴发送。这样沿用用户熟悉的技能与聊天历史。桌面原生跳转属于首轮实测项。

## 参考项目的实际复用

上游：[chuspeeism/dashi-taskboard](https://github.com/chuspeeism/dashi-taskboard)，版本 1.1.26，提交 `6a79ef522238ff11681cb85a9d803d19442a3d00`。

纳入 SQLite 卡片、评论与关系的五个源码文件，原内容保留在 `vendor/dashi-taskboard/`，附 Apache-2.0 LICENSE 和 NOTICE。本项目的五阶段、工作流 token、迁移、历史聊天整理、Codex 插件接口与 React 界面独立实现。

没有引入上游的云同步、Jira、自动认领、Tauri 与注入式桌面控制。首版保留解决个人需求直接需要的卡片、记录与可选层级。

## 实现层级

| 层级 | 实现 | 职责 |
| --- | --- | --- |
| 卡片与关系 | 上游 TaskboardDatabase | SQLite 卡片、评论、版本和一层父子关系 |
| 个人工作流存储 | workbench-store.mjs | 草案、进展、成果、本轮授权、迁移映射与整理建议 |
| 工作流服务 | workbench.mjs | 构思与实施隔离、验收、停止锁、过期写回保护、历史建议确认 |
| Codex 接口 | mcp.mjs、http.mjs、broker.mjs、codex.mjs | 全局入口、App-only 操作、本机共享服务与只读聊天状态/分页 |
| 原生聊天写回 | steward-workflow 技能与 cardctl.mjs | 真实聊天 ID 绑定、草案/进展/成果写回；未加载 MCP 时使用相同服务 |
| 工作台 | workbench.jsx、workbench.css | 顶部记录灵感、紧凑五栏、指针/键盘拖拽、详情、整理和归档 |

AI 不能调用 App-only 的准备、阶段切换与历史建议确认来替代用户决定。写回携带本轮 token，目标和草案版本变化或回退后拒绝旧结果。构思保存草案可延续当前回合；实施不能自行改写已选草案。

历史整理只分析所选聊天，建议显示理由、置信度和角色原文。保存前重核来源和目标；无可核对验收证据时不会建议已结项。导入只建立卡片与聊天关联，不接管执行。

## 数据迁移与恢复

旧库 `data/steward.json` 原文不变，额外保留带哈希的 JSON 备份。迁移先写临时 SQLite、完成 checkpoint 并关闭后替换为 `data/workbench.sqlite`。版本冲突防止并发覆盖；迁移锁只恢复已确认死亡进程的锁。

旧单任务项目折成单卡，多任务/显式分组保留父子关系。保留说明、标准草案、项目目标、主聊天、关联聊天、交付、资料和问答记录，旧 ID 与新 ID 映射可追溯。

设置备份生成 SQLite 快照。手动恢复需先停本插件服务，恢复快照影响卡片数据，不影响原生聊天。回到旧版使用原提交 `463c202` 与保留的 JSON；新旧版本不能同时运行在相同端口和数据目录。

## 减法审查

删除必须先建大卡、必须先确认标准才能构思、重复显示单任务父卡，以及盘问结束就送验的假设。用卡片与原生聊天覆盖首版实际目标，暂不增加自动认领、流程编排、多层任务、云账户或新的模型配置。旧代码保留作历史回归与回滚依据，不进入新版运行入口。
