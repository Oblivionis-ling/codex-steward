# 个人管家 · Codex 桌面插件

用五栏看板推进 Codex 任务。默认一项任务一张卡、一个主聊天；需要分工时再拆成子任务，跟进执行、交付和验收。

当前版本 **0.2.3-dev.2（0.2.3 开发版）**，加入默认单层卡和历史聊天进度判断，保留主聊天占用恢复。本机已安装并启用 `personal-steward@ling-local`。仓库：[Oblivionis-ling/codex-steward](https://github.com/Oblivionis-ling/codex-steward)，保留 `v0.1.0`、`v0.2.0`、`v0.2.1` 和 `v0.2.2` 版本；0.2.3 后续改动继续迭代，尚未打最终版本标签。

## 使用流程

1. 重新打开 Codex，在左侧「个人管家」入口打开看板；也可以在新聊天输入「打开个人管家」。空看板引导可以点 × 或「暂时跳过」关闭，不必创建大卡。
2. 已有 Codex 任务：点击首页「AI 整理现有聊天」，勾选聊天，让 AI 建议归属、阶段和一句进展。核对原文依据、调整阶段，勾选进度确认后保存。单聊天默认生成一张卡；多项任务归入同一个项目时才显示项目与子任务。
3. 新目标：直接新建一张任务卡，填写目标后即可继续操作。需要拆分时，在卡片的 ⋯ 菜单或详情里添加子任务、让 AI 拆分；原任务、主聊天、标准和资料保留。
4. 单任务直接出现在对应栏，不重复显示一张项目大卡。拆分后，子任务仍沿用这五栏；一次只展开一个项目。
5. 拖动任务卡左侧手柄，从灵感池移到待启动。检查任务说明，让 AI 拟定验收标准，编辑后勾选确认，点「保存并确认标准」。
6. 将卡拖到进行中，保存的说明和标准直接发送到主聊天，同时打开独立聊天区。首次建立主聊天，返工和后续执行沿用它；标准尚未确认时，先打开验收设置，不会启动。
7. 查看卡片的一句进展和实际执行状态。Codex 提交逐条验收证据并结束执行后，任务进入待验收。历史整理的进度是对现有聊天的判断，不会创建或启动执行。
8. 将待验收卡拖到已结项，核对交付证据后确认。历史聊天导入的待验收卡可核对原文后确认结项；目标、来源或执行改变时需重新核对。单任务只需一次验收；多子任务全部结项后项目进入待验收，项目结项仍由你确认。

聊天整理无需先建项目。列表显示 workspace 中未归档的聊天，标明总数，超过 30 条可「加载更多」，每批最多勾选 30 个。插件自己的整理辅助聊天默认隐藏，可勾选「显示整理辅助聊天」查看；新增聊天后点「刷新」。可以归入已有项目或小卡；全新分组由 AI 拟定名称，经确认后创建。生成中关闭窗口不会丢失草案，重新点首页入口，在「继续查看整理建议」中恢复。关闭按钮、取消或 Escape 均可退出整理窗口。

进度建议显示判断理由、置信度和带角色的原文引用。长聊天保留最初目标和最新需求，避免把旧成果当成新需求已完成。仅有 AI 自称完成时最多建议待验收；没有可核对依据时降低置信度、保守判断。项目阶段与任务建议一起预览；编辑后需要重新勾选确认，来源聊天或目标卡变化时会要求重新分析。

五阶段：**灵感池 → 待启动 → 进行中 → 待验收 → 已结项**。运行中、等待回答、聊天被占用和失败属于执行状态，不增加看板栏。

已有主聊天出现「聊天被占用」时，本轮尚未启动，卡片保留原阶段。点「主聊天」打开独立聊天区，可「在 Codex 打开」核对原聊天，结束当前执行后「重试原聊天」。桌面端空闲时也可能继续持有聊天写入权；若仍被占用，可点「创建接续主聊天」，确认复制历史并开始执行。原聊天保留为关联，后续阶段沿用新的主聊天；取消不会创建聊天。返工意见会保留供重试使用。原聊天仍在执行时，接续会被阻止并提示先处理原聊天。

宽窗口把聊天放在看板右侧；窄窗口上下排列，可通过「收起聊天」给看板更多空间。选择小卡的「主聊天」或聊天区下拉框查看和切换，输入补充说明后点击发送，也可按 Ctrl+Enter。聊天草稿按小卡保存在本机，长消息可以展开全文；「在 Codex 打开」进入原生聊天。

## 推进与回退规则

大小卡都拖动左侧手柄到相邻栏，目标栏会显示能否移动及原因。键盘操作：空格拿起，左右方向键选栏，回车放下，Escape 取消。进行中小卡仍需完整交付证据与真实执行结束后自动送验。

| 操作 | 结果 |
| --- | --- |
| 小卡启动 | 使用已确认的说明和标准；项目自动进入进行中 |
| 主聊天被占用，尚未启动 | 保留原阶段、已确认标准与旧成果；打开原聊天处理或重试 |
| 确认创建接续主聊天 | 复制历史后执行，原主聊天保留为关联；后续使用新主聊天 |
| 普通回复结束 | 留在进行中；没有完整证据不会自动送验 |
| 完整证据 + 真实执行结束 | 小卡进入待验收，精选成果与决定保存为项目资料 |
| 用户通过验收 | 单任务卡及其项目一起结项；多子任务全部结项时项目待验收 |
| 小卡回退 | 先取得停止确认，再回退；保留聊天与已有成果 |
| 大卡回退 | 停止所属执行，**全部小卡回到待启动**，包括灵感、待验收、已结项的小卡 |
| 已结项项目追加需求 | 单任务卡和项目回待启动，保留聊天与成果；多子任务项目回待启动，历史子任务阶段保留 |

大卡回退会先展示受影响清单。停止过程中其他窗口不能新建或启动该项目的小卡；停止失败会保留实际阶段并显示原因。旧执行结果不能覆盖已回退的阶段。

修改任务说明或验收标准会清除确认。待验收小卡修改目标后回到待启动；已结项小卡须先回退。历史成果保留，当前标准必须有本轮对应证据才可结项。

## 项目内的资料、问答与历史聊天

- 资料来自主聊天提交的精选成果、关键决定和结论，也可手动添加、编辑或移除。移除后保留原文，供历史引用追溯。
- 支持单条、所选批量归档：分类、总结、重点、标签、重要度、关联和行动建议。行动建议经你点击确认后进入灵感小卡。
- 资料可按正文、分类、标签和归档状态查找。首页搜索项目与任务。
- 项目问答和日期回顾结合卡片状态与项目资料，保存可打开原文的编号引用；行动建议经确认后成为小卡。
- 首页「AI 整理现有聊天」或项目详情的历史聊天入口：先勾选，再分析所选正文。AI 建议归属、任务阶段和项目进度，确认后生成卡片或关联。保留已有卡的说明、标准和主聊天；不伪造执行记录或验收标准。没有自动扫描全部聊天。
- 每张小卡一个主聊天，可以添加其他关联聊天；同一聊天不能同时作为多张小卡的主聊天。

默认资料归档由宿主聊天处理。可在设置中选用自己的 OpenAI 兼容模型，这只影响资料归档。任务执行、AI 拆分、标准、问答和回顾使用本机已有 Codex 登录。

## 本地保存与升级

统一工作目录：`F:\workspace`。插件源码与运行文件：`F:\workspace\codex-steward`。

- 数据：`data/steward.json`，写入保留上次版本 `steward.json.bak`。
- 首次迁移 0.1.0 时额外保留 `steward.v1.<原文件哈希>.backup.json`，后续写入不会覆盖它。
- 原记录迁入「原有记录」项目，原待办保持 ID、正文和完成状态。
- 手动导出在 `data/backups/`。备份包含项目、小卡、资料、结论及聊天引用，不含 API Key。
- 导入合并，不覆盖同 ID 冲突，不恢复执行、草案或后台整理任务。恢复后先核对主聊天的实际状态。
- 自选模型 Key 仅保存在本设备的界面存储，调用时交给本机服务与所选模型接口，不写入数据文件、备份或日志。界面存储不可用时仅本次打开可用。
- 任务服务重新连接后，不把旧任务冒充运行中；保留阶段和成果，提示你核对主聊天后继续或回退。

真实数据、依赖、构建产物与临时 QA 文件不提交 Git。截图均使用隔离模拟资料，实际空库的创建引导可关闭。

## 开发、安装与预览

需要 Node.js 22.12+ 或 24、已登录的 Codex，以及 PATH 中的 `node.exe` 和 `codex.exe`：

```powershell
npm ci
npm run build
npm test
npm run install:codex
```

安装脚本注册本地市场 `ling-local`，升级插件并写入本机绝对路径。移动目录后重新执行。当前 Codex 会话不会自动加载新增工具，重新打开应用或使用新聊天刷新。

```powershell
npm start
```

预览：`http://127.0.0.1:43187/`，与插件共用真实数据。只读示例：`http://127.0.0.1:43187/?demo=1`。启动任务后显示插件自己的聊天区，可通过「在 Codex 打开」进入原生主聊天。

服务只监听本机、拒绝跨域和 DNS 重绑定。多个 MCP 实例通过共享服务协调执行；默认端口被旧服务占用时会提示版本或数据目录冲突，避免连接错库。请勿用另一端口同时对同一数据目录运行执行服务。
